# Build 42 Lua gotchas

Found in real Test Ground runs on Build 42. Each one cost a failed run.

- **God mode.** The invincible flag (`setInvincible`) stops nothing, because the damage code doesn't check it. Real god mode is a cheat, and `isGodMod()` reads it, but outside debug mode Lua can't turn it on. `player:getCheats()` returns an object Lua can't index ("attempted index: set of non-table"), and `setGodMod` needs the role capability `ToggleGodModHimself`, which the default roles don't allow. Always read it back, and never let zombies reach the player unless it reads back true. Test Ground's guarded fights put zombies down at 2.2 tiles, then stop, remove the zombies and heal (`getBodyDamage():RestoreToFullHealth()`) on the first wound.
- **Menu and pause.** `OnTick` doesn't fire at the main menu (use `OnFETick`) or while the game is paused (`OnRenderTick` still fires). A loaded save sits paused; unpause it with `UIManager.getSpeedControls():SetCurrentGameSpeed(1)`.
- **Files.** Lua can only read and write files in `Zomboid\Lua\`, and the game refuses writes to `.csv`, so write CSV data as `.txt`.
- **Square flags.** `sq:Is(flag)` is gone in B42. Use `sq:has(IsoFlagType.x)`, and `props:has("name")` for properties.
- **Cars from Lua.** Cruise control drives a car with no input: `setRegulatorSpeed(kmh)` then `setRegulator(true)`. `setForceBrake()` brakes for 1 s, and braking also turns cruise control off. `addVehicleDebug` adds ±11 degrees of random yaw, so line the car up with `setAngles` before driving.
- **Fights without god mode.** For real contact (zombies grabbing, knocking down), restore health every tick instead: `getBodyDamage():RestoreToFullHealth()`, `setInfected(false)`, and reset the stats (`getStats():reset(CharacterStat.ENDURANCE)` and the same for `PANIC` and `FATIGUE`; B42 stats go through `CharacterStat`). Watch health anyway and fall back to put-downs if a hit gets through between ticks. Swing from Lua with `player:pressedAttack()` after facing the zombie. A launch with `-debug` gives real god mode.
- **Compare like with like.** Start every run from the same place on the vanilla map (Test Ground's `start = westpoint`), not where the save loaded: a fresh unmodded save loads elsewhere, and a modded map may not load without its mod at all. Teleporting far needs a wait until the squares exist (`getCell():getGridSquare` non-nil around the spot) before spawning or surveying.
- **Old plan files.** A saved plan outlives the code that wrote it. Check what the plan really holds before reading a result as the new code's, and make tools say which source they used (map data, or a local fallback).
- **pcall is not silent.** In game, every error pcall catches (a Java throw, or indexing nil) still prints a stack trace and counts as an error on screen. Check for nil before calling (unloaded squares return nil from `getGridSquare`), skip calls that are known to fail (god mode outside `-debug`), and switch off a per-tick call after its first failure. In a mock, wrap `pcall` to count failures by message.
- **Kahlua limits.** A file's main chunk may have at most 200 locals. Put new constants in one table (`local K = {}`, then `K.NAME = ...`).
- **Heavy Lua in the harness itself.** Kahlua is slow at big-table work: `table.sort` over a step's ~34k frame times froze the game for 9 s at a step's end, and the freeze looked like a mod hitch. Keep per-frame bookkeeping constant-cost (a running histogram, not a list to sort), and time the harness's own work so a slow part shows up in the trace.
- Unattended runs stall silently when options.ini has `focusloss=true`: the game pauses whenever its window isn't in front, OnTick stops, and nothing is logged. Read it with `getCore():getOptionPauseOnFocusloss()` and log it at start. Keep an OnRenderTick watchdog that unpauses (`UIManager.getSpeedControls():SetCurrentGameSpeed(1)`) for the whole job, not only before it starts. Append the trace to disk as the run goes, so a killed run still leaves evidence.
- Forest is in the map's zones, not in streets.xml or worldmap.xml: `getWorld():getMetaGrid():getZonesAt(x,y,0)` works without loading the area; a zone type containing "Forest" (Forest, DeepForest) marks woods.
